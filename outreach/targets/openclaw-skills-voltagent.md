## Route

Two steps. The list only links to skills already published on ClawHub
(clawhub.ai, OpenClaw's skill registry), so publish there first, then open a PR.

List rules (CONTRIBUTING.md): the skill must be on ClawHub with a clean
security status, have a SKILL.md, a description of 10 words or fewer, and "real
community usage" (brand-new skills are refused; no number given). One link per
author per area. PR title `Add skill: <author>/<skill>`, with the ClawHub link in
the body. Add the line at the end of the category file in `categories/`
(here `security-and-passwords.md`).

## Publishing to ClawHub

- CLI: `npm i -g clawhub`, `clawhub login` (prints a one-time code and URL;
  approve with GitHub; the account must be old enough to pass the upload gate).
- `clawhub skill publish ./skills/package-trust-check --dry-run`, then
  `clawhub skill publish ./skills/package-trust-check --slug package-trust-check
  --name "npmscan package trust check" --version 1.0.0 --categories
  security,development --topics "npm,supply-chain,mcp"`.
- Everything published is released under MIT-0. The user accepted this on
  2026-10-29.
- `.clawhubignore` (and `.gitignore`) inside the skill folder decide what gets
  uploaded. `skill-card.md` and `_meta.json` are generated by ClawHub.
- Names `package-trust-check` and `npmscan` were unused on 2026-10-29.

- Most ship only `SKILL.md`. All of steipete's skills are like this, and so is

  `EVAL-REPORT.md`; scan suspicious).
- Others ship `references/` docs (checklists, report templates), not tests.

So test prompts are allowed but unusual. Leave ours out with `.clawhubignore`:
users don't need them, and ours describe real malicious-package incidents.

## Security scan

ClawScan combines VirusTotal, an LLM review and SkillSpector, using the OWASP
Agentic Skills Top 10. It asks whether capabilities are disclosed and match the
stated purpose. Flagged for: undeclared env vars, broad unscoped capabilities.

- Scan status `suspicious` is common (27 of 52), even on steipete's skills.
  `steipete/mcporter` got it for "broad MCP, auth, config, local command, and
  daemon capabilities without enough scoping".
- That is separate from the moderation flag (`isSuspicious`), which hides the
  skill. At least one scan-suspicious skill (shawnpana/browser-use) is in the
  list, but aim for clean anyway.
- Our skill should do well: it is read-only, needs no API key (so no
  `requires.env`), and already says not to install or publish anything. Say
  plainly in the setup section that it calls one remote MCP server,
  `https://npmscan.com/api/mcp`, and nothing else.

## OpenClaw setup section to add to SKILL.md

The skill calls npmscan MCP tools, so OpenClaw users must connect the server
first. OpenClaw supports remote MCP via `mcp.servers` in `openclaw.json`
(`url`, `transport: "streamable-http"`) or `openclaw mcp add`. Check the exact
command in a real OpenClaw install before publishing (`openclaw mcp doctor
--probe`).
